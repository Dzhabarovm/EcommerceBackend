# EcommerceBackend

Техническое задание (ТЗ) на разработку e-commerce платформы
1. Общие сведения
    • Название проекта: E-commerce платформа для продавцов и покупателей.
    • Цель проекта: Разработка масштабируемой и безопасной e-commerce платформы, предоставляющей функциональность для продавцов и покупателей.
    • Целевая аудитория: Продавцы (владельцы магазинов) и покупатели (пользователи платформы).
2. Функциональные требования
2.1 Функции для пользователей и продавцов
    • Регистрация и аутентификация через OTP:
        ◦ Регистрация с использованием номера телефона.
        ◦ Аутентификация через шестизначный OTP-код, отправленный через Telegram-бота или SMS.
    • Просмотр списка товаров с фильтрацией и поиском.
    • Добавление товаров в корзину.
    • Оформление заказа и покупка товаров.
    • Отслеживание статуса заказов.
    • Подача заявки на статус продавца.
      После одобрения заявки на статус продавца появятся функции:
                                    ▪ Добавление товаров (с описанием, ценой, изображением, количеством в наличии).
    • Редактирование и удаление товаров.
    • Просмотр статистики о продажах и заказах.
2.2 Административная панель
    • Управление пользователями, продавцами и товарами.
    • Управление заявками на статус продавца.
    • Управление заказами и платежами.
    • Статистика по продажам и пользователям.
    • RBAC (ролевой доступ) и двухфакторная аутентификация для администраторов. 
3. Нефункциональные требования
3.1 Производительность и масштабируемость
    • Использование кэширования (Redis) для ускорения работы или в БД.
    • Контейнеризация (Docker) для упрощения деплоя и масштабирования.
    • Облачное развертывание (Azure, AWS).
3.2 Безопасность
    • Аутентификация через OTP:
        ◦ Шестизначный OTP-код, отправляемый через Telegram-бота или SMS.
        ◦ Ограничение времени жизни OTP (5 минут).
        ◦ Ограничение количества попыток ввода OTP (3 попытки).
    • Защита от CSRF, XSS и SQL-инъекций.
    • Ограничение доступа к административной панели.
    • Обязать использование HTTPS на всех этапах.
    • Реализовать шифрование чувствительных данных (например, номеров телефонов).
    • Добавить регулярные аудиты безопасности и обновления зависимостей.
       
3.3 Документация и тестирование
    • Автоматическая генерация API-документации (Swagger/OpenAPI).
    • Тестирование API через Postman.
    • Юнит-тесты для ключевых сервисов.
    • Добавить раздел с технической документацией (API, архитектура).
    • Создать пользовательские руководства для продавцов и администраторов.
4. Технологический стек
4.1 Backend
    • Язык программирования: C#.
    • Фреймворк: ASP.NET Core 8.
    • ORM: Entity Framework Core.
    • База данных: PostgreSQL.
    • Логирование: Serilog.
    • Очереди задач: Hangfire (для фоновых задач).
    • Паттерны разработки: CQRS (через MediatR, если нужно).
    • Валидация данных: FluentValidation.
    • Маппинг объектов: AutoMapper.
    • Telegram-бот: Использование библиотеки Telegram.Bot для отправки OTP.
4.2 Frontend (Jetpack Multiplatform)
    • Язык программирования: Kotlin.
    • Фреймворк: Jetpack Compose Multiplatform.
    • Сеть: Ktor Client или Retrofit.
    • Сериализация: Kotlin Serialization.
    • Локальное хранилище: SQLDelight.
    • Загрузка изображений: Coil.
    • Навигация: Voyager или Decompose.
    • DI: Koin или Kodein.
4.3 Инфраструктура
    • CI/CD: GitHub Actions, GitLab CI/CD или Azure DevOps.
    • Мониторинг: Application Insights (Azure) или Prometheus + Grafana.
    • Хранение медиафайлов: Хостинг или виртуальный сервер.
5. Бизнес-логика заявок на статус продавца
    1. Пользователь подает заявку на получение статуса продавца.
    2. автоматическая предварительная проверка заявок (например, через API антифрода). 
    3. Администратор рассматривает заявку.
    4. В случае одобрения пользователю отправляется договор для подписания.
    5. После подписания договора аккаунт активируется как "Продавец" и в приложении появляются дополнительные возможности продава.
    6. сроки рассмотрения заявки администратором (например, 48 часов). 
    7. Реализовать уведомления пользователя о статусе заявки.
6. Регистрация и аутентификация через OTP
6.1 Процесс регистрации
    1. Пользователь вводит номер телефона на форме регистрации.
    2. Система генерирует шестизначный OTP-код и отправляет его через Telegram-бота.
    3. Пользователь вводит полученный код.
    4. Если код верный, система создает учетную запись.
6.2 Процесс аутентификации
    1. Пользователь вводит номер телефона на форме входа.
    2. Система генерирует новый OTP-код и отправляет его через Telegram-бота.
    3. Пользователь вводит полученный код.
    4. Если код верный, пользователь получает доступ к своей учетной записи.
6.3 Техническая реализация
    • Генерация OTP: Использование криптографически безопасного генератора случайных чисел.
    • Отправка через Telegram-бота: Интеграция с Telegram API.
    • Хранение OTP: Временное хранение в Redis с ограниченным временем жизни или в БД.
    • Проверка OTP: Сравнение введенного кода с сохраненным в кэше.

    • Развернутая e-commerce платформа с базовым функционалом.
    • Возможность масштабирования и поддержка мобильных клиентов.
    • Надежная система безопасности, включая аутентификацию через OTP с использованием Telegram-бота.
    • Удобная административная панель (при необходимости).

Архитектура и структура проекта
E-commerce платформа будет состоять из нескольких проектов в одном решении (Solution) в Visual Studio 2022. Это позволит лучше разделить ответственность и соблюдать принципы чистой архитектуры.
Структура решения:
    1. Api – основной API-проект (ASP.NET Core 8).
    2. Application – слой бизнес-логики (CQRS, MediatR).
    3. Domain – модели данных, доменные сущности.
    4. Infrastructure – работа с базой данных (EF Core, PostgreSQL), интеграции (Redis, Telegram-бот).
    5. Tests – модульные и интеграционные тесты.
Обоснование такой структуры:
    • Разделение ответственности по слоям.
    • Легкость в расширении функционала.
    • Упрощенная поддержка и тестирование.
